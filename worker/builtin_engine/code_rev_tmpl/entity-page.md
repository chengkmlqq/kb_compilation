# 业务对象 / 关联规则 实体页模板

## A. 业务对象页（entity-b）

- **slug**：`entity-b-<md5(类别|canonical)[:10]>`
- **page_type**：`business_ontology`
- **标题**：业务对象名（不带类型前缀；指代定语后的核心名）
- 页面必须含 **5 节**：标题 + 类型定位 + 基本信息 + 关联规则 + 关联对象 + 原文关联

```markdown
# 元数据

**业务对象**　7-元模型元素

## 基本信息

| 字段 | 内容 |
|---|---|
| 定义 | 描述数据的数据，涵盖业务元数据、技术元数据与管理元数据 |
| 来源文档 | 《中国移动省级NG2-BASS(v5.0)技术规范元数据管理分册.docx》；《附录一：…核心元模型规范.docx》 |

## 关联规则

| 要求类型 | 内容 | 来源 |
|---|---|---|
| [[entity-r-ro006-xxxxxxxxxx|元数据存储范围要求]] | 应存储业务元数据、技术元数据、管理元数据… | 《…元数据管理分册.docx》 |

## 关联对象

| 关联对象 | 关系类型 | 关系说明 | 来源 |
|---|---|---|---|
| [[entity-b-xxxxxxxxxx|核心元模型]] | 作用对象 | 规则《元数据存储范围要求》规定：… | 《…》 |

## 原文关联

**《中国移动省级NG2-BASS(v5.0)技术规范元数据管理分册.docx》**
- [[longsentence/xxxxxxxxxx-xxxxxxxx|元数据管理范畴：…]]
```

要点：
- 基本信息表**不含**「本体类型」「业务标识」行；「来源文档」一律用**完整文件名**（含版本与扩展名），多条用 `；`。
- 跨文档合并的实体：folder_ids 累加（每个来源文档的分类目录），source_refs 累加，原文关联按 `**《文件名》**` 分组追加。
- 关键规则表由规则卡的「约束对象」反向填充；无规则时保留空表头，**禁止**「（待补充）」占位符。
- 关联对象表**不含**规则行，不允许自引用。

## B. 关联规则页（entity-r）

- **slug**：`entity-r-ro<两位类别号>-<md5(canonical)[:10]>`
- **page_type**：`rule_ontology`
- 页面必须含 **5 节**：标题 + 类别定位 + 基本信息 + 规则结构 + 原文关联

```markdown
# OLAP查询响应时间要求

**关联规则**　6-性能要求

## 基本信息

| 字段 | 内容 |
|---|---|
| 要求类型 | 性能要求 |
| 约束对象 | [[entity-b-xxxxxxxxxx|经营分析系统]] |
| 相关对象 | [[entity-b-xxxxxxxxxx|OLAP工具]]（客体） |
| 来源文档 | 《中国移动省级NG2-BASS(v5.0)技术规范总册.docx》 |

## 规则结构

| 字段 | 内容 |
|---|---|
| 主体 | 经营分析系统 |
| 条件 | 对于90%以上的OLAP查询 |
| 指标 | 响应时间 ＜ 25秒 |

## 原文关联

- [[longsentence/xxxxxxxxxx-xxxxxxxx|OLAP查询：对于90%以上的OLAP查询，从用户发出查询请求…应小于25秒]]
```

要点：
- 关联规则卡 **不合并**（每个分册的卡独立成页）；title 为 LLM 一句话概括（≤20 字），不要求逐字原文。
- `evidence` 字段（原文关键片段，逐字）用于锚定原文关联与 slug 生成；**无长句链接的要求卡 SKIP**。
- 约束对象必须是业务实体名；表格列名/字段名/码值/表号不得作约束对象。
